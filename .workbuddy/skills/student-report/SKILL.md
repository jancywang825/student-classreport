# 学员报告生成 Skill（demo 版 v2.0）

> 版本：v2.0（2026-11-23）新增「使用事件上报」：每次生成报告后自动上报 `report-created` 到 `POST /api/ai/reportSkillUsage`，失败不阻断交付。此前含署名/课次展示覆盖、赏识话术边界修复、总结题名配色对齐、强调收敛、未作答识别 + 原题展示、头图信息层级优化、逐图点评 + 点击放大、报告质检。需求文档见项目根目录《学员阶段性学习报告_Skill需求文档.md》v2.0。

## 命令行参数速查
`--product-name` 课程名（精确）｜`--class-seq` 课次（**注意：有的课程后台用纯数字如 `10`，传「第10次课」查不到课节；先用 `getCClassList` 确认**）｜`--co-teacher` 联席/教务（用于筛学生）｜`--teacher` 主讲署名覆盖（仅展示，不改真实数据）｜`--seq-label` 课次展示名覆盖｜`--token` x-token（缺省读缓存）｜`--out` 输出目录｜`--no-qc` 跳过质检｜`--no-report-usage` 跳过使用上报。
**课次定位技巧**：先 `client._get('/api/cClass/getCClassList', {'productId': pid, 'classSeq': 目标})` 看返回；数字/中文不匹配时改用纯数字；课节原名（如「考后总结」）可用 `--seq-label "第10次课 · 考后总结"` 兼顾用户口径与真实课节名。

## 目标
- **类型 A · 阶段性学习报告**（单学员，PDF）
- **类型 B · 单次课堂报告**（单学员，PDF）
- **类型 B · 批量模式**（v0.5 新增）：输入「课程名称 + 第几课节 + 联席/教务名称」，从**管理后台接口**取数，**一次性产出全班学生**的当节课单次课堂报告，以**自包含 HTML** 呈现，**顶部姓名切换器**点击即切换。报告维度与单学员版完全一致。

## 执行流程
### 批量 HTML（推荐入口）
```bash
# 演示（无需凭证）
PY=/Users/jancy/.workbuddy/binaries/python/versions/3.14.7/bin/python3
$PY scripts/generate_html_batch.py --mock \
  --product-name "L-初三二物理" --class-seq "2026-10-17 讲次" \
  --co-teacher "蔡笑铮" --out <项目>/reports

# 真实（首次自动打开沙箱浏览器登录，输入用户名/密码后自动取 token 并缓存）
$PY scripts/generate_html_batch.py \
  --product-name "L-初三二物理" --class-seq 3 --co-teacher "蔡笑铮" --out <项目>/reports
```
1. 取数：resolve() → 学生列表 → productId+classSeq 定位 classId → 全班考勤 + 全班小黑板分析。
2. 内容：`report_content.py` 按 **类型 B 相同维度** 构建每个学生的 blocks（analysisResult 字段容错解析，缺字段按考勤/评级推导）。
3. 渲染：`generate_html_batch.py` 输出**单个自包含 HTML**（绿色渐变头图 + 姓名切换芯片 + 白卡 + 指标色卡，小黑板图 base64 内嵌，离线可看；含打印样式）。
4. 复核外发：**必须经老师复核确认后才能发给家长**。

/Users/jancy/.workbuddy/binaries/python/envs/default/bin/python scripts/generate_report.py \

## 报告维度（B 类，单学员与批量完全一致）
头图（**{学员}学习报告 → 课程名称 → 第几次课 → 上课时间**）→ 信息卡（**仅 主讲老师 / 联席老师**）→ 指标色卡（本讲评级/**课堂星星：接口有值才显示**/小黑板正确率/课后作业/出勤）→ **课堂亮点（不足 3 条整块隐藏）** → 小黑板完成情况与分析（**按 全部正确 / 有错 / 未作答 三模块分别总结，重要数据带颜色**）→ 三个小黑板分类展示区 → 下次课小目标 → 落款。**模块编号动态生成，隐藏亮点后自动顺延（一/二/三）**。
**头图信息层级（v1.4）**：绿色色块行序为「标题 → 课程名称 → 课次 → 上课时间」；上课时间取课节 `classBeginTime`/`classEndTime`，用 `format_class_time()` 格式化为「2026年10月6日（周二） 13:30–15:50」，**禁止显示 ISO 原始串**；信息卡删除 4 项冗余（课程全称/课次/学员名称/小黑板日期），只留双老师，理由：学员已在标题、课程与课次已在色块、日期已在上课时间。质检新增「头图信息层级」检查项。
**未作答识别与展示（v1.5）**：①`analysisResult: []`（图片右下角标「未参与作答」的黑屏图）**必须归入未作答分区**，旧逻辑因无题目落到「全部正确」是缺陷；用同轮次原题索引补出题名/知识点。②`resolve()` 额外返回 `question_index`（按 `roundNo` 聚合全班原题名/知识点/含题干样图，同课次题目相同）。③未作答照片自动裁出**白底原题题干**（`_crop_light_region()` 纯 PIL 亮度检测列/行区间，纯黑图返回 None 时按候选取同轮次样图），右侧以蓝色「未作答/未参与作答」徽章 + 原题题目 + 涉及知识点 + 补齐建议展示，**不再写「错误的点：空白未提交」**。④总结关键字（全部正确/有错需订正/未作答 + 作答正确/存在错误/未完成/补交等）一并着色强调；`_highlight_text()` 用占位符法按长度降序替换，避免重叠片段造成 HTML 嵌套错乱。⑤质检新增「未作答识别」「未作答展示」两项；图片去重检查只核主图（原题裁切图为额外内嵌）。
小黑板展示规则：接口一条记录 = 一轮小黑板照片（roundNo + 唯一 imageUrl），其 analysisResult 是该照片上 1~2 道题的分析。**文字按题自身结果归三类；照片按轮次归一类（有错 > 未作答 > 全部正确）并以 imageUrl 全局去重，一张照片只出现一次**；正确率按已批改题（正确/有错）计算。已删除原「我们一起努力的方向」与「可以提升的点/潜力点」二分结构。
**逐图点评表格（v1.2）**：每个分类区内以「一图一行」的左右表格呈现——左列为该张小黑板原图（**可点击放大**灯箱查看，支持点空白/×/ESC 关闭），右列为该张图的三段点评：**做得好的点（绿）/ 错误的点（橙）/ 学生的卡点（蓝）**，分别取自接口的 `note`+`topic_knowledge` / `errors`+部分作答 / `stuck_at`；空白未提交归入「错误的点」并明确标注；某段无内容自动隐藏；双题照片的点评合并到同一行。窄屏（<620px）自动上下堆叠。
**阅读优化与一致性（v1.3）**：①总结重要数据颜色提示——正确率 ≥90% 绿、70~89% 琥珀、<70% 橙红，各类题数用分区色；`hl_bullets` 渲染。②点评按语义自动分段（`_split_semantic()` 按 `；。;换行` 切短句，不切英文句点以免误伤公式），逐行展示。③课堂亮点不足 3 条整块隐藏，编号自动顺延。④**亮点结论必须由真实数据推导**：仅 `n_blank==0 且 n_total>0`（全部完成）才允许「按时完成/书写作答完整/掌握扎实」，杜绝「1 题完成、7 题未做」却写正面的缺陷；未出勤不凑亮点。
**报告质检（v1.3）**：`scripts/quality_check.py`，生成后自动执行并输出 `reports/报告质检_{课程}_{课次}.md`；维度①数据正确性（学员数/照片去重无漏/题数守恒/正确率/评级/出勤/点评题名归属/图片内嵌）、维度②前后逻辑一致（亮点vs完成数据、亮点vs考勤、亮点隐藏规则、总结vs分区、分区标题张数、编号连续、结论vs分区、无空模块）；FAIL/WARN 分级，FAIL 会在终端提示。图片下载带 3 次重试（防偶发 502 造成缺图 FAIL）。v1.5/v1.6 追加「未作答识别/展示」「文案简洁」「强调收敛」「强调不加粗」检查项。
**强调收敛与文案精简（v1.6，配色见 v1.8）**：①总结模块只保留数字（总题数/已批改/正确率）与分区标签着色，**「」中的知识点/方法名**着色强调（v1.6 初版统一用 `KP_COLOR=#0B7A55`，**v1.8 起改为跟随该行分区色**）；「存在错误/订正/未完成/补交/作答正确/思路完整」等评价类词**不再高亮**。②所有强调**只用 `<span>` 改字色、禁止 `<b>` / 加粗**（`.hl`、`.kp` 均 `font-weight:400`）；`_highlight_text()` 输出 span，`_emphasize_quoted()` 给逐图点评的「」题名套 `.kp`。③删除不携带信息的模板套话（「本题为部分作答，解题步骤尚未完成」「建议结合老师讲解订正」「课堂内容吸收扎实」「详见下方说明」「再把解题思路讲一遍」等），总结行精简为「标签 · N 题：题名列表」，未作答区去掉空泛建议句；`_review_lines()` 的兜底文案也压到最短。
**赏识型话术（v1.7）**：孩子写满一页推导、画出草图却只看到「错误的点」是体验缺陷。①`report_content.py` 新增 `_split_clauses()` / `_is_positive_clause()` / `_praise_from_wrong()`：按分句极性（**不能用单字「不」做负面词，「不等式」是数学名词**）从 `note` 提炼正面分句（如「换元列第二式正确」「函数草图形状基本正确」「不等式推导正确」）；提炼不出但有动笔事实（`部分作答` / errors / note）时给有依据的鼓励（「已经动笔写出部分推导，动手尝试本身就是很好的开始」）。②有错单元 `good` 段写具体肯定并**排在待订正之前**；待订正段剔除已提炼的正面分句避免重复；空白未提交不套用鼓励。③卡点话术改为「停在「X」，下一步可以先复核这一步」，段标题中性化：「做得好的点 / 待订正的点 / 卡住的地方」。④混合题照片（一题未做、另一题做对）在未作答专用布局里也展示「做得好的点」。⑤质检新增「赏识型话术」项（有错单元须有具体肯定、无空泛表扬/全盘否定/重复、标题中性），共 25 项。
**总结题名配色对齐（v1.8）**：「二、小黑板完成情况与分析」里每个分类行的「」题名颜色必须与**该行分类标签同色**，一行一色：`全部正确`→`#0AA860` 绿、`有错需订正`→`#D08A3E` 咖黄/橙、`未作答`→`#4A7FB5` 灰蓝；首行总览（题数/正确率）沿用 v1.3 分档色不受约束；逐图点评的 `.kp` 仍是柔和墨绿 `#0B7A55`（`KP_COLOR` 现在只对应此用途）。实现：`_summary_modules()` 里 quoted marks 由 `KP_COLOR` 改为 `TONE[key]`。质检新增「题名配色对齐」项（学员级核对 marks 色值 + 全局 HTML 层核对每行 span 实际颜色），共 26 项。

## 边界与已知限制（demo）
- 批量真实模式尚未用真实账号联调：登录页 URL 默认 `基础域/login`，令牌提取轮询 localStorage 常见键名（x-token/token/accessToken…）与 cookie，失败时回退手动粘贴；首次联调可能需按实际站点调整。
- `analysisResult` 字段名未定，已做容错解析（grade/stars/homework/correct/total/summary/praise/improve…），首次联调后按实际字段校准。
- 单学员 PDF 模式仍用本地 zip + 飞书快照；飞书快照仅第 1、2 讲。
- 报告外发前必须经老师复核。
